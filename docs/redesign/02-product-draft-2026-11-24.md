# 재설계 2/5 상품 도메인 초안 (2026-11-24)

> **1차 시도 보관본입니다.** 2026-11-24에 선생님 9단계 방식으로 처음부터 다시 설계하기로 했습니다. 이 문서는 지우거나 고치지 않고 참고용으로 남깁니다. 새 설계는 `docs/design/`에서 진행합니다.

사용자가 보낸 항목 표(상품, 상품카테고리, 상품 제작 정보, 상품가격, 상품원가구성요소, 디테일 정보)와 2026-11-24 대화 내용을 합친 초안입니다. 할인 관련 항목(할인율, 할인정액, 상품 판매가)은 할인 도메인에서 다루므로 뺐습니다.

모든 테이블 끝에 시스템 칸 4개(생성일시 createdAt, 생성자 createdBy, 수정일시 updatedAt, 수정자 updatedBy)가 있습니다. 생성자·수정자는 회원·관리자·시스템이 섞이므로 FK가 없습니다.

## 3. 전체 구조

```
[기준 정보]
 카테고리 ◀─┐(상위 카테고리)     시즌   컬러   사이즈 그룹 ─< 사이즈
            └──────┘             소재   거래처   과세 구분
 실측 항목   고시 항목   디테일 항목 ─< 디테일 항목 값

[핵심]
 상품 ─< 상품 컬러 ─< SKU (사이즈를 가리킴)
 상품 ◀──관련 상품──▶ 상품 (상품끼리 M:N)

[상품에 딸린 것]
 상품 ─< 상품 미디어 / 상품 소재 / 상품 실측 / 상품 디테일 정보
     ─< 상품 전시 카테고리 / 상품 검색어 / 상품 정보 고시

[생산·가격]
 상품 ─< 상품 생산 차수 ─< 상품 원가 구성 항목
 상품 ─< 상품 가격 ──(근거)──▶ 상품 생산 차수

(─< 는 1:N)
```

## 5. 모델링 개념 적용

### ① 관계수와 관계 유형
| 관계 | 관계수 | 관계 유형 |
|---|---|---|
| 카테고리 → 하위 카테고리 | 1:N | 재귀(자기 참조) 1:N |
| 상품 ↔ 관련 상품 | M:N | 재귀 M:N, 연결 테이블로 풂 |
| 상품 ↔ 전시 카테고리 | M:N | 연결 테이블(상품 전시 카테고리) |
| 상품 ↔ 소재 | M:N | 연결 테이블(상품 소재), 관계의 속성 = 혼용률 |
| 상품 ↔ 디테일 값 | M:N | 연결 테이블(상품 디테일 정보) |
| 상품 → 상품 컬러 → SKU | 1:N, 1:N | 핵심 계층 |
| 사이즈 그룹 → 사이즈 | 1:N | |
| 상품 → 생산 차수 → 원가 항목 | 1:N, 1:N | 헤더 - 상세 |
| 상품 → 가격 | 1:N | 기간별 행(이력) |
| 시즌·과세 구분·사이즈 그룹 → 상품 | 1:N | 기준 정보 참조 |

정보 고시는 품목마다 항목이 달라서, 칸이 아니라 항목마다 1행으로 둡니다.

### ② 선택성
| 관계 | 필수 / 선택 |
|---|---|
| 상품 → 대표 분류 카테고리, 사이즈 그룹, 과세 구분 | 항상 필수 |
| 상품 → 시즌 | 선택 (시즌 없는 상시 상품) |
| SKU → 상품 컬러, 사이즈 | 항상 필수 |
| 상품 → 컬러·SKU·썸네일·소재·실측·고시 필수 항목·현재 가격 | 작성 중엔 선택, 판매 중으로 바꿀 때 필수 |
| 상품 → 전시 카테고리, 관련 상품, 검색어, 디테일 정보 | 선택 |
| 생산 차수 → 공급사, 컬러 / 원가 항목 → 거래처 | 선택 |
| 미디어 → 상품 컬러 | 선택 (비어 있으면 공통 이미지) |

### ③ 식별자 상속
| 방식 | 테이블 | 이유 |
|---|---|---|
| 비식별 + 단독 키 | 상품, 상품 컬러, SKU, 생산 차수, 기준 정보(디테일 값 제외) | 다른 테이블이 가리킵니다. SKU는 주문·재고가 가리키므로 키가 길어지는 것을 막습니다. |
| 식별 + 복합 키 | 미디어, 소재, 실측, 디테일 정보, 전시 카테고리, 관련 상품, 검색어, 정보 고시, 원가 항목, 가격, 디테일 항목 값 | 부모 없이는 의미가 없고, 복합 키가 중복을 막아 줍니다. |

디테일 항목 값은 상품 디테일 정보가 가리키지만, 항목 없이는 의미가 없고 가리키는 곳이 한 곳뿐이라 식별 관계로 두었습니다.

### ④ 슈퍼타입/서브타입
옷·액세서리·가방·신발을 테이블로 나누지 않고 상품 유형 구분 칸 하나로 처리합니다. 유형마다 다른 실측·디테일·고시 항목은 기준 정보의 "적용 상품 유형" 칸으로 걸러 냅니다. 새 유형이 생기면 기준 정보에 행만 추가합니다.

## 6. 가격 관리 설계

### 원칙
| 원칙 | 내용 |
|---|---|
| 정가는 사람이 정합니다. | 원가를 참고해 결정·확정합니다. |
| 원가는 계산합니다. | 원가 항목(사용량 × 단가)의 합입니다. 저장하지 않습니다. |
| 판매가는 할인 도메인에서 계산합니다. | 상품 도메인은 정가까지만 다룹니다. |
| 이력은 행으로 남깁니다. | 가격이 바뀌면 행을 추가합니다. 이력 테이블은 따로 없습니다. |
| 지우지 않습니다. | 가격·원가 행은 취소·폐기 상태로 바꿉니다. |
| 금액은 정수(원)입니다. | 소수 계산을 하지 않습니다. |

### 업무 흐름
1. **신상품 가격**: 생산 차수(작성 중) → 원가 항목 입력 → 생산 차수 확정 → 상품 가격(작성 중: 정가, 근거 차수, 목표 배수, 사유) → 마진율 확인 → 가격 확정 → 상품 판매 중(확정된 현재 가격 1개 검사)
2. **가격 변경**: 새 가격 행(시작 일시 = 바꿀 날, 미래면 예약 변경) → 확정하면서 앞 행의 종료 일시를 새 시작 일시로 맞춤
3. **리오더**: 새 생산 차수 → 원가 확정 → 정가 변경 여부는 사람이 판단(자동으로 바뀌지 않음)
4. **잘못 입력**: 작성 중은 수정·취소 / 확정했지만 시작 전이면 취소(앞 행 종료 일시 원복) / 이미 시작된 가격은 취소하지 않고 새 행으로 바로잡음

### 상태
- 상품 가격: 작성 중 → 확정 → (시작 전만) 취소 / 작성 중 → 취소
- 생산 차수: 작성 중 → 확정 / 작성 중 → 폐기 (가격의 근거로 쓰인 확정 차수는 폐기 불가)

### 규칙
| # | 규칙 | 이유 |
|---|---|---|
| 1 | 같은 상품의 확정 가격끼리 기간이 겹치지 않음 | 현재 가격이 하나여야 함 |
| 2 | 종료 일시 > 시작 일시 | 기간이 거꾸로면 안 됨 |
| 3 | 정가 > 0, 정수 | 0원·소수 금액 금지 |
| 4 | 확정된 가격의 정가·시작 일시는 수정 불가 | 주문·할인 표시의 근거 |
| 5 | 이미 시작된 확정 가격은 취소 불가 | 그 가격에 팔렸을 수 있음 |
| 6 | 근거 생산 차수는 같은 상품 + 확정 상태 | 다른 상품 원가로 마진 계산 방지 |
| 7 | 확정된 생산 차수의 원가 항목은 추가·수정·삭제 불가 | 원가 근거 고정 |
| 8 | 판매 중 상품은 확정된 현재 가격이 꼭 1개 | 가격 없는 판매 방지 |
| 9 | 판매 중 상품의 현재 가격 뒤에 빈 기간 금지 | 종료 후 판매가 막히는 것 방지 |
| 10 | 가격·원가 행 삭제 금지 | 근거 자료 |

### 계산 값 (저장 안 함)
| 값 | 계산 |
|---|---|
| 현재 정가 | 확정 + 시작 일시 ≤ 지금 < 종료 일시(또는 비어 있음) |
| 원가 합계 | Σ(사용량 × 단가) |
| 정가 기준 마진율 | (정가 − 원가 합계) ÷ 정가 |
| 실제 원가 배수 | 정가 ÷ 원가 합계 |
| 공급가액 / 부가세 | 정가 × 100 ÷ (100 + 부가세율) / 정가 − 공급가액 (끝전 처리 **검증 필요**) |

### 다른 도메인과의 연결
| 도메인 | 연결 |
|---|---|
| 할인 | 현재 정가를 받아 판매가 계산 |
| 장바구니 | 가격 저장 안 함, 볼 때마다 계산 |
| 주문 | 정가·판매가·부가세율을 주문 상품에 스냅샷 |
| 결제 | 화면 금액과 서버 재계산 금액이 다르면 중단 |
| 리포트 | 총 매출이익 = 주문 스냅샷 금액 − 판매 당시 생산 차수 원가 |

### 경우의 수
| 상황 | 처리 방향 |
|---|---|
| 장바구니에 담아 둔 사이 가격 인상 | 항상 현재 가격 표시, 결제 직전 변경이면 다시 확인 |
| 주문 후 가격 인하 | 주문 금액 그대로(스냅샷), 차액 환불 정책은 미정 |
| 자정에 가격 변경 | 한국 시간 기준으로 저장·비교 |
| 할인 직전 정가 인상으로 할인율 부풀림 | 종전 가격 규정 **검증 필요**, 가격 행 미삭제가 근거 |
| 과세 → 면세 변경 | 상품 칸이라 이력이 없음, 주문 스냅샷으로 지난 주문은 안전 |
| 컬러만 리오더 | 생산 차수의 컬러 칸 사용, 정가는 상품 단위 |
| 판매 종료 상품 | 가격 행 유지, 재판매 시 새 행 |

### 가격 테이블 설계 방법 비교 (참고)
| 방법 | 내용 | 비고 |
|---|---|---|
| 상품에 가격 칸 | 값을 고침 | 이력 없음 |
| 현재 + 이력 분리 | 상품에 현재, 이력 테이블에 변경 | 어긋날 위험, 예약 불가 |
| 기간 행 (SCD Type 2) | 시작·종료 일시 행 | 이 초안의 방식 |
| 버전 번호 | 버전 + 현재 여부 | 날짜별 조회·예약 어려움 |
| 가격 유형별 행 | 정가 / 사업자가 / 임직원가 | 사업자 전용가가 생기면 |
| 가격표(헤더 + 상세) | 시즌·채널·통화별 가격표 | 대형·다채널 |
| 상품 / 컬러 / SKU 단위 | SKU 추가 금액 등 | 사이즈 추가금은 미결정 |
| 수량 구간 가격 | 많이 살수록 쌈 | 도매·단체 주문 |

## 7. 테이블 모양 6가지 (모든 도메인 공통)

| 모양 | 특징 | 예 |
|---|---|---|
| ① 기준(마스터) | 목록 값, 단독 PK, 상태 = 사용/중지 | 컬러, 사이즈, 과세 구분 |
| ② 핵심 엔티티 | 다른 테이블이 많이 가리킴, 상태 흐름 | 상품, SKU |
| ③ 1:N 상세 | 부모ID + 순번 PK (식별 관계) | 상품 미디어, 원가 항목 |
| ④ M:N 연결 | 양쪽 ID가 PK, 관계의 속성 | 상품 소재(혼용률), 관련 상품 |
| ⑤ 기간·버전 행 | 시작·종료 일시, 겹침 금지 | 상품 가격 |
| ⑥ 기록(로그) | 쌓기만 함 | (고객 도메인의 로그인 시도 등) |

## 8. 미결정·확인 필요

1. 카테고리 "모델명"을 코드로, "분류"를 상품 분류/전시 구분으로 해석한 것이 맞는지 확인
2. 사이즈·컬러별 추가 금액(SKU 추가 금액 칸) — 룩플 확인 후
3. 추가 원가 항목(디자인비, 샘플비, 수입 관세)
4. 사이즈별 원가가 다를 때 원가 항목에 사이즈 칸이 필요한지
5. 가격 확정 권한(승인자 칸)
6. 모델 착용 정보(키·몸무게·착용 사이즈)
7. 재입고 알림은 재고 쪽
8. **검증 필요**: 품목별 법정 고시 항목, 부가세 포함 표시, 할인 표시용 종전 가격 기준, 원가 기록 보관 기간, 부가세 끝전 처리

## 9. 답하지 못한 사용자 질문 (2026-11-24, 재시작 전에 받은 것)

사용자가 이미지와 함께 보낸 질문입니다. 답하기 전에 처음부터 다시 설계하기로 해서, 새 설계에서 다룹니다.

1. **상품 소재 추가 항목**(사용자 작성): 소재명, 소재코드, 소재 모델명, 소재 분류(실의 굵기 예: 20수·30수, 제직·편성 방식), 소재 상태, 소재 성분, 소재 혼용률, 소재에 따라 신축성·두께감·무게감·비침이 달라짐, 세탁·관리 정보
2. **상품 사이즈 추가 항목**(사용자 작성): 사이즈 표기 단위, 사이즈 이름, 상품 실측 사이즈, 사이즈 측정 분류(상의·아우터·하의·잡화마다 측정 방법·오차·신축성이 다름), 사이즈 표기(US·EU 등 국가별, 해외 판매 시 대표 국가 표기), 사이즈 측정 항목, 사이즈 측정 위치
3. 시즌 테이블의 핵심 칸을 최대한 많이 추천해 달라
4. FK가 없는 테이블은 다른 테이블과 어떻게 연결되나
5. 거래처 주소가 필요하고, 주소가 2개 이상일 수 있음
6. 거래 일시·거래처 발주는 발주 테이블을 따로 둘지, 발주 도메인으로 크게 잡을지
7. 과세 구분 테이블에 면세가 같이 있는지, 과세·면세의 핵심 칸이 더 있지 않은지
8. 고시 항목 테이블 이름이 짧다 → "상품정보제공고시 항목"처럼 구체적으로. 칸도 너무 적다. 법정 항목(국가법령정보센터 발췌)을 담을 수 있는지 확인 필요
   - 의류(9): 제품 소재(섬유 조성·혼용률 백분율, 기능성은 성적서·허가서), 색상, 치수, 제조자(수입품은 수입자 함께, 병행수입 여부로 대체 가능), 제조국, 세탁방법 및 취급 시 주의사항, 제조연월, 품질보증기준, A/S 책임자와 전화번호
   - 구두/신발(8): 제품 주소재(운동화는 겉감·안감 구분), 색상, 치수(발길이: 해외 사이즈면 국내 사이즈 병행 mm, 굽높이: 굽 재료 쓰는 여성화만 cm), 제조자, 제조국, 취급 시 주의사항, 품질보증기준, A/S 책임자와 전화번호
   - 가방(9): 종류, 소재, 색상, 크기, 제조자, 제조국, 취급 시 주의사항, 품질보증기준, A/S 책임자와 전화번호
   - 패션잡화(모자·벨트·액세서리)(8): 종류, 소재, 치수, 제조자, 제조국, 취급 시 주의사항, 품질보증기준, A/S 책임자와 전화번호
