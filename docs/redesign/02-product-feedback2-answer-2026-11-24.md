## 0. 질문별 짧은 답

| 질문 | 답 |
|---|---|

| 발주 | 상품 도메인이 아니라 **구매·재고 도메인**으로 따로 잡는 것을 추천합니다. |

## 1. 상품 소재: 섬유와 원단 나누기

보내 주신 칸들을 보면 두 가지가 섞여 있습니다.
- **섬유**: 면, 폴리에스터, 울. 실의 재료입니다.
- **원단**: "30수 면 싱글저지", "옥스포드 코튼". 섬유로 실을 뽑아 짠 천입니다.

번수(20수, 30수), 짜는 방식, 원단 모델명, 혼용률, 신축성·두께감은 모두 **원단**의 성질입니다. 그래서 상품은 원단을 가리키고, 원단이 섬유 혼용률을 가집니다.

```
섬유 ─< 원단 성분 >─ 원단 ─< 상품 원단 >─ 상품
                     ├─< 원단 특성 (신축성·두께감 기본값)
                     └─(원가 항목이 가리킴: 원단비)
```

같은 원단을 셔츠 10개에 쓰면 혼용률을 원단에 **한 번만** 적으면 됩니다(정규화).

| 보내 주신 칸 | 들어간 곳 |
|---|---|
| 소재명, 소재코드, 소재 모델명 | 원단 이름, 원단 코드, 원단 모델명 |
| 소재 분류(번수, 제직·편성 방식) | 원단의 실 번수, 원단 조직 구분, 원단 조직 이름 |
| 소재상태 | 원단 상태 |
| 소재 성분, 소재 혼용률 | 원단 성분(섬유 + 혼용률) |
| 소재에 따라 디테일이 달라짐 | 원단 특성: 상품 디테일 정보의 **기본값**으로 채워 주고, 최종값은 상품에서 정합니다(안감이나 패딩에 따라 달라지므로). |
| 세탁, 관리 정보 | 세탁 기호(기준) + 상품 세탁 기호 + 원단 관리 주의사항 |

## 2. 상품 사이즈

| 보내 주신 칸 | 들어간 곳 |
|---|---|
| 사이즈 표기 단위 | 사이즈 그룹의 사이즈 표기 단위 구분 |
| 사이즈 이름 | 사이즈 (이미 있음) |
| 상품 실측 사이즈 | 상품 실측 (이미 있음) |
| 측정 분류(상의, 아우터, 하의, 잡화 / 오차, 신축성) | **측정 분류** + 측정 분류 항목(허용 오차). 카테고리가 측정 분류를 가리킵니다(자켓 → 아우터 실측). |
| 국가별 표기(US, EU), 대표 표기 | **사이즈 국가별 표기** + 사이즈 그룹의 기본 표기 국가 |
| 사이즈 측정 항목, 측정 위치 | 실측 항목 + 측정 위치 설명·그림 |

**법과 연결되는 부분이 있습니다.** 신발은 "해외 사이즈로 표기하면 국내 사이즈(mm)를 함께 표기"해야 합니다. 국가별 표기 테이블이 있으면 "신발에 US 표기가 있으면 KR(mm) 행도 있어야 한다"는 규칙으로 막을 수 있습니다(**검증 필요**).

```
카테고리(자켓) ──▶ 측정 분류(아우터) ─< 측정 분류 항목 >─ 실측 항목(어깨너비)
사이즈 그룹 ─< 사이즈 ─< 사이즈 국가별 표기
```

## 4. FK가 없는 테이블은 어떻게 연결되나

**연결선은 N 쪽에만 적습니다.** 예를 들어 학생 카드에는 "3반"이라고 적지만, 3반 카드에 학생 30명을 적지는 않습니다. 시즌 1개에 상품이 여러 개(1:N)이므로 **상품이 시즌ID를 들고 있고**, 시즌 테이블에는 FK가 없습니다. 그래도 연결은 되어 있습니다.

| FK가 없는 테이블 | 누가 가리키나 |
|---|---|
| 시즌 | 상품 |
| 컬러 | 상품 컬러 |
| 섬유 | 원단 성분 |
| 세탁 기호 | 상품 세탁 기호 |
| 측정 분류 | 카테고리, 측정 분류 항목 |
| 실측 항목 | 측정 분류 항목, 상품 실측 |
| 과세 구분 | 상품 |
| 거래처 | 원단, 생산 차수(제조사·공급사·수입자), 원가 항목, 거래처 주소·담당자 |
| 상품정보제공고시 품목 | 상품 유형, 상품, 고시 항목 |
| 품질보증 정책 | 상품 유형, 상품 |

**이 질문을 보다가 찾은 문제가 있습니다.** 사이즈 그룹, 실측 항목, 디테일 항목, 고시 항목의 "적용 상품 유형"이 FK가 아니라 **글자 칸**이었습니다. 이러면 "의류"와 "옷"처럼 다르게 적어도 막을 수 없습니다. 그래서 **상품 유형** 테이블을 만들어 모두 FK로 바꿨습니다(이 결과 실측 항목은 측정 분류로 대체됐습니다).

## 6. 발주는 어디에

**구매·재고 도메인을 따로 두는 것을 추천합니다.** 이유는 세 가지입니다.

- **생산 차수와 발주는 다른 것입니다.** 생산 차수는 "얼마에 만드는가"(원가 근거, 상품 도메인)입니다. 발주는 "언제, 어느 SKU를 몇 장, 언제까지 받나"(주문서)입니다.
- **발주의 흐름은 재고와 이어집니다.** 발주 → 입고 → 재고 증가 → 재입고 알림 순서입니다. 그래서 재고와 같은 도메인에 두는 것이 자연스럽습니다.
- **거래 일시는 발주에 있습니다.** 발주 일시, 납기 예정 일자, 입고 일시가 이 도메인에 들어갑니다.

예상 테이블은 발주(헤더), 발주 상품(SKU별 수량, 생산 차수ID), 입고, 입고 상품, 재고, 재고 원장입니다. 거래처는 상품 도메인의 기준 정보를 그대로 가리킵니다.

**경우의 수 하나**: 재설계 목록(고객 → 상품 → 주문 → 결제 → 배송)에 **재고가 없습니다.** 주문할 때 재고를 잡아야 하므로 **상품 → 구매·재고 → 주문** 순서를 추천합니다.

면세는 **같은 테이블의 다른 행**입니다. 테이블은 "종류 목록"이고, 행이 실제 종류입니다.

|---|---|---|---|

옷과 잡화는 거의 모두 과세입니다. 면세와 영세율은 해외 판매처럼 드문 경우에 대비한 행입니다(**검증 필요**).

## 10. 상품 칸 보강

### 판매량과 반품률은 상품에 저장하지 않습니다

판매량은 **주문 상품을 세면** 나오고, 반품률은 **반품 수량 ÷ 판매 수량**으로 계산합니다. 상품에 숫자로 저장하면 주문이 들어올 때마다 고쳐야 하고, 하나라도 빠지면 실제와 달라집니다(파생 속성).

다만 실무에서는 매번 세면 느려지므로 **리포트용 집계 테이블**(상품·SKU별 일별 판매 수량, 판매 금액, 취소 수량, 반품 수량)을 따로 둡니다. 이 테이블은 주문·클레임이 끝난 뒤 리포트 단계에서 만듭니다. 원본 기록을 바탕으로 매일 다시 계산하므로 틀려도 고칠 수 있습니다.

## 11. SKU

**SKU는 쇼핑몰이 정합니다.** 정해진 표준은 없습니다. 표준은 **바코드(GTIN, 국내는 880으로 시작하는 13자리)**이며, GS1 코리아에 가입해서 받습니다(**검증 필요**). 편의점처럼 다른 판매처에 납품할 때 필요합니다.

**SKU가 무엇으로 이루어졌는지는 이미 칸으로 드러나 있습니다.** SKU는 상품 컬러ID(= 상품 + 컬러)와 사이즈ID를 가지고 있어서, 이 FK 두 개가 곧 구성입니다. SKU 코드 규칙은 "상품 코드-컬러 코드-사이즈 코드"(26FW-SH001-BK-M) 하나로 정하고, DB 규칙으로 맞는지 검사합니다. 단일 브랜드라 규칙이 하나뿐이어서 규칙 테이블은 두지 않는 것을 추천합니다.

**SKU에 칸 1개를 추가합니다**: `UK | 바코드(GTIN) | barcode | 표준 바코드 번호입니다. 아직 없으면 비어 있고, 있으면 겹칠 수 없습니다.` 사이즈 추가 금액은 아직 정하지 않았습니다.

## 12. 재고 도메인이 없어서 빠진 것인가

**일부는 맞습니다.** 상품 도메인은 "이 상품이 **무엇인지**"(이름, 원단, 사이즈, 원가, 정가)만 담습니다. 숫자가 계속 움직이는 것은 다른 도메인에 들어갑니다.

| 빠진 것 | 들어갈 도메인 |
|---|---|
| 재고 수량, 안전 재고, 창고 위치, 발주, 입고, 재입고 알림 | 구매·재고 |
| 판매량, 구매자 수 | 주문 (집계는 리포트) |
| 반품률, 교환 사유 | 클레임 |
| 리뷰, 평점, 선호도 | 리뷰 |
| 할인가, 할인율 | 할인 |

## 14. 남은 것

1. 시즌의 "선택" 칸 3개(룩북 이미지, 룩북 공개 일시, 목표 수량·금액)를 넣을지 정해야 합니다.

3. 아직 정하지 않은 것: 모델 착용 정보, 사이즈 추가 금액.
4. **검증 필요**: 고시 품목 분류(액세서리가 패션잡화인지 귀금속인지), 제조연월을 여러 차수일 때 어떻게 표시할지, 품목별 품질보증 기간, 아동복 KC 인증, 교환·반품 제한 사유, 부가세 증빙, 섬유와 세탁 기호의 법정 표기.
