# 재고 구조 미리보기 (2026-11-27, 확정 아님)

배송 설계를 마친 날 "재고 설계방법 모두"를 미리 들어 본 내용입니다. **아직 사용자가 정하지 않았습니다.** 다음 작업에서 이 결정 지점부터 바꿀 것을 받고, 이어서 기능·정책(안전 재고 수량, 예약 판매, B급 판매, 재입고 알림 기간 등)과 처리 방식(동시성, 예약 만료 작업)을 정합니다.

## 다른 도메인에서 넘어온 것

| 어디서 | 재고에서 할 일 |
|---|---|
| 주문 | 결제할 때 재고 예약, 선물 옵션 변경 때 예약 이동, 선물 예약 만료 = 수락 기한, 구매·생산 8개(부자재, 자재 발주·품목, 자재 입고·품목, 생산 발주·수량, 사급 자재 지급, 매입 대금 지급, 발주 이력) |
| 결제 | 결제 시작 때 예약 연장, 가상계좌 입금 기한까지 예약 유지 |
| 배송 | 출고·출고 상품·출고 상태 이력 초안(`../05-delivery/02-tables.md` "재고로 넘길 초안"), 피킹, 재고 등급이 바뀌면 판매 가능 재고가 바로 줄어야 함, 연쇄 부족 때 먼저 결제한 주문 우선, 불량·분실·파손 재고 처리, 반송 상자 입고, 출고 창고 위치, 반품 도착 위치, 배송 출고ID(1:1), 회수 상품 → 출고 상품 |
| 주문(공급 문제) | 공급 문제를 일으킨 재고 기록(등급 변경) 연결 |

## 구조 결정 지점과 추천

| # | 결정 지점 | 일반적인 방법 | 추천 | 이유 |
|---|---|---|---|---|
| 1 | 범위 | 수량만 / + 위치 / + 입출고 업무 / + 구매·생산 | 모두 하되 두 묶음(재고 핵심 + 입출고 → 구매·생산) | 구매·생산만 8개라 한 번에 하면 결정 지점이 섞임 |
| 2 | 세는 단위 | SKU / SKU×위치 / **SKU×위치×등급** / 물건 1개마다 / 로트 | SKU×위치×등급 | 하자 발견 때 옮기지 않고 등급만 바꿔 판매 가능 재고에서 바로 뺌 |
| 3 | 수량 저장 | 잔고만 / 원장만 / **잔고 + 원장** / + 월말 마감 | 잔고 + 원장 + 월말 마감 | 원장 = 거래 내역(왜 품절됐나), 잔고 = 통장 잔액(빠른 화면), 마감 = 실사·금액 기준 |
| 4 | 판매 가능 재고 | 실재고 / − 예약 / **− 예약 − 안전 재고** / + 입고 예정 | 실재고 − 예약 − 안전 재고(정상 등급, 판매 위치) | 저장하지 않고 계산 |
| 5 | 예약 | 없음 / 주문 상품 칸 / **예약 테이블(주문 상품 1개 = 1행)** / 예약 + 할당 분리 | 예약 테이블 | 1개 1줄과 짝, 연장·이동이 한 행에서 처리 |
| 6 | 위치 | 없음 / **1단 + 위치 구분** / 계층 / 트리 | 1단(출고 창고, 반품 센터, 불량 보관, 촬영·샘플) + 판매 위치 여부 | 위치가 몇 곳뿐 |
| 7 | 등급 | 위치로 구분 / **잔고 키에 등급 칸** / 등급 테이블 | 등급 칸(정상, 검수 대기, 불량, 보류) | 값이 적음. 등급 변경도 원장 2행 → 공급 문제가 가리킴 |
| 8 | 이동 기록 | 원장 하나 / 업무 테이블만 / **업무 전표 + 공통 원장** | 전표 = 왜, 원장 = 수량 변화 | 추가 배송비 ↔ 결제와 같은 생각 |
| 9 | 전표 나누기 | 하나 / 업무마다 / **칸이 다른 것만 따로** | 입고, 출고, 반품 입고는 따로, 위치 이동·등급 변경·분실·파손·실사 차이는 재고 조정 하나 | |
| 10 | 출고 | **초안 그대로 + 피킹 위치·일시** / + 피킹 작업 묶음 | 초안 그대로 | 출고 완료(집하) 때 예약 확정 + 원장 출고 = 재고가 실제로 주는 순간 |
| 11 | 입고·발주 | 입고만 / **완제품 발주 → 입고** / + 생산·자재 | 첫 묶음은 완제품 발주, 둘째 묶음에서 생산·자재 | 입고 예정일(재입고 안내, 예약 판매), 부분 입고 |
| 12 | 반품 입고 | 바로 정상 / **반품 센터 + 검수 대기 → 검수 결과로 등급 변경** | 검수 대기 | 판정은 환불, 재고 변화는 재고. 반송도 같은 길 |
| 13 | 실사 | 없음 / **실사 전표 → 확정 때 조정 자동** | 실사 전표 | 손실 근거, 전산 수량 기준 시각 |
| 14 | 안전 재고·재주문점 | SKU 칸 / 잔고 칸 / **재고 기준 설정 테이블** | 기준 설정 따로 | 잔고는 트리거 요약, 설정은 관리자 값 |
| 15 | 재입고·재고 부족 알림 | 다른 도메인 / **재고** | 재고 | 재고 변화에서 시작 |
| 16 | 재고 금액 | 수량만 / **입고 단가만 기록** / 원장마다 금액 | 입고 단가만 | 원가 방식은 회계 기준과 함께(**검증 필요**) |
| 17 | 로트 | 없음 / **원장에 입고 품목 FK** / 로트 단위 잔고 | 원장에 입고 품목 FK | 생산 차수 불량 추적 |
| 18 | 예약 만료·연장 | 만료 일시만 / + 연장 사유 / **+ 예약 이력** | 예약 이력까지 | "담을 때 있었는데 왜 품절" 문의 |
| 19 | 채널 | **온라인 창고만** / 매장 공유 / 외부몰 | 온라인만 | 위치 구분에 매장을 나중에 추가 가능 |
| 20 | 창고 간 이동 | 즉시 / **2단계(출발 → 이동 중 → 도착)** | 2단계 | 이동 중에는 어디서도 못 팖 |
| 21 | 잔고 맞추기 | 앱이 고침 / **원장을 넣으면 트리거가 맞춤 + 마이너스 금지** | 트리거 | 마지막 1개 동시 구매처럼 앱이 못 막는 동시 요청 |
| 22 | 예약 판매 | 안 함 / **확정 발주의 입고 예정 수량 안에서만** / 제한 없음 | (할 경우) 입고 예정 한도 | 할지는 기능 결정에서 |

## 생각하지 못했을 수 있는 경우

1. 마지막 1개를 두 명이 동시에 결제
2. 예약 만료 직전에 결제창을 엶(결제 시작 때 연장)
3. 선물 수령인이 바꾼 옵션이 품절(변경을 막고 원래 예약 유지)
4. 반품이 검수를 통과해 품절이 풀림 → 재입고 알림
5. 실사 중에 주문이 들어옴
6. 전산에는 있는데 선반에 없음 → 공급 문제 + 조정(분실)
7. 불량 재고를 B급으로 팔지
8. 판매 중지 상품의 남은 재고
9. 촬영용·샘플 재고
10. 포장 상자 같은 소모품(추천: 관리 안 함)
11. 입고 수량이 발주보다 많거나 적음(부분 입고, 초과 거부)
12. 회계 기간 말 재고 금액 평가(**검증 필요**)
