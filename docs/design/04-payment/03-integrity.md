# 6단계: 데이터 무결성 검증 조건: 결제 (2026-11-26)

결제 16개와 공통 금융기관 테이블(`02-tables.md`)의 검증 조건입니다.

- **검사 방법의 뜻**(CHECK, UK, FK, 생성 칸, 권한, 트리거, 앱, 점검), **DB·앱 나누기 기준**, **앱 + 점검 규칙**은 `../01-customer/03-integrity.md` 앞부분과 같습니다.
- **공통 조건 G-01~G-16**(시스템 칸, 상태·구분 값 목록, 금액 0 이상 정수, 암호문·검색값·표시값 형식, 기록 테이블은 추가만)은 다시 적지 않았습니다.
- 개수는 모두 **133개**입니다.
  - 결제 PM-01~PM-128: 128개
  - 주문 추가 O-127~O-129: 3개(`../03-order/03-integrity.md`에도 있음)
  - 고객 추가 C-81~C-82: 2개(`../01-customer/03-integrity.md`에도 있음)
- **프로시저는 쓰지 않습니다.** DB 로직은 트리거와 CHECK·UK·FK에만 두고, 나머지는 앱 쓰기 함수가 맡습니다.
- 금융기관 조건(표준 코드·결제사 코드 UK, 구분 값, 지우지 않음)은 G 공통과 FK(삭제 제한)로 충분해서 번호를 따로 매기지 않았습니다.
