# 배송 3~5단계: 테이블 정의 (2026-11-27)

배송 도메인 25개 테이블(413칸)을 정의합니다. 결정과 이유는 `01-design-methods.md`, 검증 조건은 `03-integrity.md`에 있습니다.

- 모든 테이블 끝에 시스템 칸 4개(생성일시, 생성자, 수정일시, 수정자)가 있습니다.
- 물리명은 카멜로 적었고, 7단계 SQL에서 스네이크로 한꺼번에 바꿉니다(2026-11-27 표기 결정).
- 다른 도메인과 연결하는 칸은 그 도메인을 설계할 때 넣습니다(사용자 규칙). 아래 "나중에 붙일 칸"으로 관리합니다.
- **출고·출고 상품·출고 상태 이력은 재고 도메인으로 넘겼습니다**(창고 일과 운송 일을 나눔). 정한 내용은 맨 아래 "재고로 넘길 초안"에 있습니다.

## 전체 관계

```
배송 방식 ─┬─< 배송 정책 ─< 배송 구역
           ├─< 배송비 정책
           └─< 배송 ──── 예외 배송 상세 (1:1, 퀵·직접 전달)
배송 업체 ─┬─< 배송 업체 계약 ─< 운임 청구 ─< 운임 청구 상세 ── 운송장
           └─< 배송 추적 상태 ─< 배송 추적 이벤트 >── 배송 추적 수신

주문 ─┬─< 배송 ─┬─< 배송 상태 이력
      │         └─< 운송장 ─< 배송 추적 이벤트
      ├─< 회수 ─┬─< 회수 상품 ── 주문 상품
      │         ├─< 회수 상태 이력
      │         └─< 운송장 (반송은 배송의 운송장을 따라감)
      ├─< 추가 배송비 청구 ─< 추가 배송비 (배송 또는 회수) ;  결제 → 추가 배송비 청구
      └─< 배송 사고 ─< 배송 사고 첨부
배송 엑셀 처리 기록 ─< 배송 엑셀 줄별 처리 결과 ── 운송장 / 회수
배송 연동 기록, 배송 추적 수신 (기록)
[재고] 출고 1 ── 1 배송 (출고ID는 재고 설계 때 붙임)
```

### 11. 회수 (ReturnShipment): ② 핵심

| 키 | 논리명 | 물리명 | 설명 |

## 재고로 넘길 초안

2026-11-27에 배송 도메인에서 정했다가 "창고 일은 재고"라는 사용자 의견으로 넘긴 것입니다. 재고 설계 때 이것을 출발점으로 씁니다.

| 테이블 | 넘기는 내용 |
|---|---|
| 출고 (②) | 상자 1개 = 1행, 상자에는 주문 하나만(합포장 금지), 출고 구분(일반, 재발송, 교환), 원래 출고ID(자기 FK), 상자 규격(극소~대), 출고 상태(출고 지시, 포장 완료, 출고 완료, 출고 취소), 출고 지시 일시, 출고 일시(재고 차감 기준), 출고 취소 사유. 배송과 1:1. 주문에 출고 보류가 걸려 있으면 출고 지시 불가. 재발송·교환은 추가 배송비 청구가 결제 완료여야 출고 지시 |
| 출고 상품 (③) | (출고ID, 주문ID) 복합 FK로 합포장 금지, (주문ID, 순번) → 주문 상품, 실제 출고 SKU(교환·오배송 확인), 살아 있는 출고 1개(조건부 UK), 상태(살아 있음, 분실, 파손, 회수됨, 반송됨, 출고 취소), 배송 사고ID, 피킹 위치·피킹 일시 |
| 출고 상태 이력 (⑥) | 트리거로 기록 |
| 요구 | 재고 등급(정상, 검수 대기, 불량 등)이 바뀌면 판매 가능 재고가 바로 줄어야 함. 하자는 피킹 때 처음 발견됨 → 공급 문제. 같은 SKU 다른 주문까지 연쇄로 부족해지면 먼저 결제한 주문 우선. 분실·파손 출고 상품의 재고 처리, 반송·반품 상자는 반품 센터 + 검수 대기로 입고, 불량 재고 처리(수선, 폐기, 협력사 반품) |
