# 쇼핑몰 DB 설계 (선생님 9단계 방식, 2026-11-24 재시작)

재설계 1차 시도(고객 26개·상품 26개)는 `docs/redesign/`에 보관했습니다. 여기서는 처음부터 차근차근 다시 설계합니다.

## 도메인 순서

고객 → 상품 → 주문 → 결제 → 배송 → 환불 → 포인트 → 이벤트

## 단계 (도메인마다 반복)

| 단계 | 할 일 | 예시 질문 |
|---|---|---|
| 1 | 도메인을 위 순서대로 하나씩 진행 | |
| 2 | 설계 방법을 묻고 답변을 정리해 저장 | "고객 테이블 설계하는 방법 모두 알려줘" → "2번째 방법에 대해서 좀 더 자세히 알려줘" → "2번째 방법과 4번째 방법의 차이점 자세히 알려줘" |
| 3 | 설계를 마치면 테이블 전체 목록을 설명과 함께 보기, 관련 테이블끼리 그룹 | "테이블 전체 목록을 설명과 함께 보여줘", "고객과 관련된 테이블 목록 보여줘" |
| 4 | 모든 테이블 끝에 시스템 칸 4개 추가 | created_by, created_at, updated_by, updated_at |
| 5 | 한글 칸 이름을 최대한 자세히 | |
| 6 | 데이터 무결성 검증 조건 목록 만들기 → 확인 후 뺄 것 빼고 반영 | "데이터 무결성을 위한 검증 조건 목록 만들어줘" |
| 7 | 테이블당 SQL 파일 하나 (MySQL 8.4) | |
| 8 | 최종 결과를 직접 확인하고, 빠진 칸 추가, 관련 칸끼리 모으기 | |
| 9 | 최종 변경 사항 검토 요청 | |

2단계 질문은 테이블 하나하나가 아니라 **결정 지점** 단위로 합니다(예: "주문 상태 관리 방법 모두 알려줘"). 결정 하나가 테이블 여러 개를 만듭니다.
