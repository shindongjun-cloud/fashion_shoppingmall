# 주문 3~5단계: 테이블 정의 (2026-11-25)

주문 도메인 14개 + 공통 2개(쇼핑몰 사업자 정보, 영업일 달력)입니다. 고객 도메인에 추가한 3개(비회원 주문 세션, 법정대리인, 보호자 구매 한도)는 `../01-customer/02-tables.md` 23~25번에 있습니다. 결정 과정은 `01-design-methods.md`, 검증 조건은 `03-integrity.md`에 있습니다.

- 시스템 칸 4개(생성일시·생성자·수정일시·수정자)는 모든 테이블 끝에 있습니다.
- 다른 도메인과 연결하는 칸은 그 도메인을 설계할 때 넣습니다(사용자 규칙). 아래 "나중에 붙일 칸" 목록으로 관리합니다.

## 전체 관계

```
고객 ─< 주문 ─┬─1 주문자 정보 (← 주문 개인정보 상태의 기준)
  │           ├─< 주문 배송지 (버전 행)
  │           ├─< 주문 상품 >─ SKU(+상품ID), 상품 가격
  │           │     ├─< 주문 상품 상태 이력
  │           │     └─< 주문 상품 옵션 변경 이력
  │           ├─< 주문 부가 서비스 >─ 부가 서비스
  │           ├─< 주문 상태 이력
  │           ├─< 주문 출고 보류 이력
  │           ├─< 주문 알림 이력
  │           ├─< 주문 관리자 메모
  │           ├─1 주문 보호자 동의 >─ 법정대리인, 보호자 구매 한도
  │           ├─1 선물하기 주문
  │           └── 대체한 주문 (자기 자신)
회원 ─< 장바구니 상품 >─ SKU
회원 ─< 법정대리인 ─< 보호자 구매 한도
비회원 ─< 비회원 주문 세션
[공통] 쇼핑몰 사업자 정보, 영업일 달력
```

| 묶음 | 테이블 | 모양 |
|---|---|---|
| 장바구니 | 1 장바구니 상품 | ④ M:N |
| 주문 기본 | 2 주문, 3 주문 상품, 4 주문자 정보, 5 주문 배송지, 6 주문 부가 서비스 | ② / ③ / ③ 1:1 / ⑤ 버전 / ③ |
| 이력·기록 | 7 주문 상태 이력, 8 주문 상품 상태 이력, 9 주문 출고 보류 이력, 10 주문 알림 이력, 11 주문 관리자 메모, 14 주문 상품 옵션 변경 이력 | ⑥ / ⑥ / ⑤ 기간 / ⑥ / ⑥ / ⑥ |
| 미성년자·선물 | 12 주문 보호자 동의, 13 선물하기 주문 | ③ 1:1 |
| 공통 | 15 쇼핑몰 사업자 정보, 16 영업일 달력 | ⑤ 버전 / ① 기준 |

# 주문 도메인 (14개)

### 1. 장바구니 상품 (CartItem): ④ M:N 연결
| 키 | 논리명 | 물리명 | 설명 |
|---|---|---|---|
| PK, FK | 회원ID | memberId | 장바구니 주인입니다. 비회원 장바구니는 브라우저에 있습니다. 회원당 최대 100종입니다. |
| PK, FK | SKU ID | skuId | 담은 SKU입니다. 같은 SKU를 다시 담으면 수량만 늘어납니다. |
| | 담은 수량 | cartQuantity | 1~99입니다. 1회 최대 구매 수량은 주문을 만들 때 검사합니다. |
| | 주문 선택 여부 | isSelected | 장바구니의 체크 표시입니다. 다른 기기에서도 그대로 보입니다. |
| | 마지막으로 담은 일시 | lastAddedAt | 정렬하고, 30일이 지나면 자동으로 삭제할 때 씁니다. |
| | 생성일시 | createdAt | 데이터가 처음 생성된 시간 |
| | 생성자 | createdBy | 데이터를 생성한 사용자 |
| | 수정일시 | updatedAt | 마지막으로 수정된 시간 |
| | 수정자 | updatedBy | 마지막으로 수정한 사용자 |

빼거나 주문하면 행을 실제로 삭제하므로 상태 칸이 없습니다. 이름, 가격, 배송비는 화면을 열 때 계산합니다(저장하면 가격이 바뀐 뒤 틀린 금액이 보임).

### 2. 주문 (Order): ② 핵심

|---|---|---|---|

| UK | 주문번호 | orderNo | 고객에게 보이는 번호입니다. "YYYYMMDD-숫자 8자리"이고, 겹치면 다시 뽑습니다. |
| UK | 주문 요청 키 | orderRequestKey | 주문서를 열 때 만든 무작위 값입니다. 두 번 클릭이나 두 탭에서 주문이 두 개 생기는 것을 막습니다. |
| | 주문 구분 | orderType | 일반 주문 또는 선물 주문입니다. 선물은 회원만 할 수 있고, 지역 추가 배송비는 0입니다. |
| FK | 고객ID | customerId | 주문한 고객입니다. 비회원이면 비회원ID입니다. 정상 회원만 주문할 수 있습니다(정지, 휴면 불가). |
| FK | 주문자 구분 | ordererType | 회원 또는 비회원입니다. (고객ID + 주문자 구분) 복합 FK로 고객과 항상 같은 값입니다. |
| FK | 주문자 본인인증 기록ID | ordererVerificationId | 비회원이 주문 전에 받은 휴대폰 본인인증입니다. 비회원은 필수, 회원은 비어 있습니다. |
| FK | 주문 당시 회원 등급ID | memberGradeId | 주문할 때의 등급입니다. 등급 혜택이 적용된 근거입니다. 비회원은 비어 있습니다. |
| | 주문 당시 연령 구분 | ageGroupType | 성인 또는 미성년(만 14~19세 미만)입니다. 만 14세 미만은 회사 정책으로 주문을 받지 않습니다. |
| | 주문 경로 구분 | orderChannelType | PC 웹 또는 모바일 웹입니다. |
| | 주문 접속 IP 검색값 | orderIpHash | 비밀키 해시입니다. 부정 주문을 찾습니다. |
| | 주문 접속 IP 표시값 | orderIpMasked | 예: 123.45.*.*. 결제 분쟁 증거입니다. |
| | 주문 기기 정보 | orderDeviceName | 예: "Chrome / Android". 법 의무가 아니라 부정 주문 판단과 통계용입니다. |
| | 주문 상태 | status | 결제 대기, 결제 완료, 결제 전 취소, 결제 만료 중 하나입니다. **돈의 상태만** 나타냅니다. |
| | 주문 상태 변경 일시 | statusChangedAt | 상태가 마지막으로 바뀐 때입니다. |
| FK | 구매 조건 약관ID | purchaseTermsId | 주문서에서 보여 준 구매 조건 버전입니다(법 8조, 13조). |
| | 구매 조건 확인 일시 | purchaseAgreedAt | "주문 내용을 확인했으며 동의합니다"에 체크한 때입니다. 필수이고, 미리 체크해 두지 않습니다(시행령 9조). |

| | 결제 완료 일시 | paidAt | 일반 주문의 출고 기한과 선물 수락 기한의 기준입니다. |

| | 결제 전 취소 사유 구분 | cancelReasonType | 고객 포기, 새 주문으로 대체, 결제 실패, 결제 만료, 보호자 동의 거절, 관리자 취소 중 하나입니다. |

### 3. 주문 상품 (OrderItem): ③ 1:N 상세 (주문ID + 순번)
| 키 | 논리명 | 물리명 | 설명 |
|---|---|---|---|
| PK, FK | 주문ID | orderId | 어느 주문의 상품인지 나타냅니다. |
| PK | 주문 상품 순번 | orderItemSeq | **물건 1개 = 1줄**입니다. 화면에서는 같은 SKU를 묶어 "× 2"로 보여 줍니다. 재고 예약, 출고, 클레임이 (주문ID + 순번)으로 가리킵니다. |
| FK | SKU ID | skuId | 지금의 SKU입니다. (SKU ID + 상품ID) 복합 FK라서 상품과 어긋날 수 없습니다. 옵션을 바꾸면 새 SKU로 바뀌고 이전 값은 옵션 변경 이력에 남습니다. |
| FK | 상품ID | productId | SKU의 상품입니다. 바꿀 수 없어서 옵션 변경은 같은 상품 안에서만 됩니다. |
| FK | 가격 적용 시작 일시 | priceStartAt | (상품ID + 이 칸)으로 상품 가격 행을 가리킵니다. 정가의 근거입니다. |
| | 상품 코드 | productCode | 주문 당시 스냅샷입니다. |
| | SKU 코드 | skuCode | 스냅샷입니다. 옵션을 바꾸면 새 값으로 바뀝니다. |
| | 상품 이름 | productName | 스냅샷입니다. |
| | 컬러 표시 이름 | colorDisplayName | 스냅샷입니다. |
| | 사이즈 이름 | sizeName | 스냅샷입니다. 셋업은 상의 사이즈입니다. |
| | 추가 옵션 내용 | optionText | 스냅샷입니다. 예: "하의 30". 없으면 비어 있습니다. |
| | 대표 이미지 주소 | imageUrl | 주문 내역에 보일 그 컬러의 이미지입니다. |
| | 과세 구분 | taxType | 스냅샷입니다. 결제사에 넘기는 면세 금액과 현금영수증에 씁니다. |
| | 교환·반품 가능 여부 | isReturnable | 스냅샷입니다. "아니오"여도 불량·오배송은 3개월까지 반품할 수 있습니다(법 17조③). |
| | 교환·반품 제한 사유 | returnLimitReason | 스냅샷입니다. 반품 불가면 필수입니다(법 17조⑥). |
| | 상품 소비자가(정가) | listPrice | 주문 당시 정가입니다. |
| | 할인 행사 할인 금액 | promotionDiscountAmount | 할인은 상품 단위로만 있어서 같은 상품의 SKU는 모두 같은 값입니다. |
| | 할인 행사 이름 | promotionName | 스냅샷입니다. 할인이 있으면 필수입니다. |
| | 판매가 | salePrice | 정가 − 할인 행사 할인 금액이고, 1원 이상입니다(CHECK). |
| | 쿠폰 할인 나눈 금액 | couponAllocatedAmount | 쿠폰 할인을 줄마다 나눈 몫입니다. 원 단위 나머지는 금액이 큰 줄에 붙입니다. 모든 줄을 더하면 주문의 쿠폰 할인 금액과 같습니다. |
| | 포인트 나눈 금액 | pointAllocatedAmount | 포인트 사용을 줄마다 나눈 몫입니다. |
| | 실결제 금액 | paymentAmount | 판매가 − 쿠폰 몫 − 포인트 몫입니다(CHECK). 취소·반품 때 돌려줄 금액입니다. |
| | 출고 기한 일자 | shipDueDate | 결제 완료일(선물은 수락일) + 3법정영업일입니다(법 15조①). 넘기면 관리자에게 알립니다. |
| | 주문 상품 상태 | status | 결제 대기, 결제 완료, 상품 준비 중, 출고 완료, 배송 완료, 구매 확정, 취소 중 하나입니다. **물건의 상태만** 나타냅니다. 반품·교환 상태는 환불 도메인에서 더합니다. |
| | 주문 상품 상태 변경 일시 | statusChangedAt | 상태가 마지막으로 바뀐 때입니다. |
| | 배송 완료 일시 | deliveredAt | 고객이 받은 때입니다. 단순 변심 7일, 판매자 사유 3개월 반품 기한의 기준입니다(법 17조). |

### 16. 영업일 달력 (BusinessCalendar): ① 기준

법과 약속에서 말하는 "N영업일 이내"(출고 3영업일, 품절·반품 환급 3영업일)를 계산하는 기준표입니다.

| 키 | 논리명 | 물리명 | 설명 |
|---|---|---|---|
| PK | 달력 일자 | calendarDate | 하루 1행입니다. 12월 1일까지 다음 해를 넣습니다. |
| | 요일 구분 | dayOfWeekType | 그 날짜의 실제 요일입니다. |
| | 법정 영업일 여부 | isLegalBusinessDay | 토·일·공휴일·대체공휴일·임시공휴일만 "아니오"입니다. **회사 휴무와 택배 휴무는 빼지 않습니다**(법정 기한에서 회사 자체 휴무일은 임의로 뺄 수 없음, CHECK). |
| | 법정 영업일 순번 | legalBusinessDaySeq | 법정 영업일마다 1씩 늘고, 쉬는 날은 직전 값을 씁니다. "기준일 순번 + 3"인 날이 3영업일 뒤입니다. |
| | 출고 가능 여부 | isShippingDay | 창고가 출고하는 날입니다. 회사 휴무면 "아니오"입니다. |
| | 택배 집하 가능 여부 | isCourierPickupDay | 택배사가 물건을 가져가는 날입니다. 배송 예정일 계산에 씁니다. |
| | 고객센터 운영 여부 | isCsOpenDay | 고객센터 안내 문구에 씁니다. |
| | 휴일 구분 | holidayType | 해당 없음, 주말, 공휴일, 대체공휴일, 임시공휴일, 회사 휴무, 택배 휴무 중 하나입니다. |
| | 휴일 이름 | holidayName | 예: 설날, 택배 없는 날. |
| | 휴일 정보 출처 구분 | holidaySourceType | 공공데이터(특일 정보 API) 또는 관리자 입력입니다. |
| | 달력 변경 사유 | changeReason | 예: "임시공휴일 지정". 이미 계산된 기한은 바꾸지 않으므로 언제 왜 바뀌었는지 남깁니다. |
| | 달력 상태 | status | 예정 또는 확정입니다. 내년 달력은 예정으로 넣고, 정부 발표 후 확정합니다. |
| | 생성일시 | createdAt | 데이터가 처음 생성된 시간 |
| | 생성자 | createdBy | 데이터를 생성한 사용자 |
| | 수정일시 | updatedAt | 마지막으로 수정된 시간 |
| | 수정자 | updatedBy | 마지막으로 수정한 사용자 |

회사 휴무가 끼면 법정 기한은 그대로 흐르는데 창고는 쉽니다. 휴무 전에 "기한이 휴무 중에 끝나는 주문"을 관리자에게 알리고, 연휴처럼 길면 공급 시기를 미리 안내해 따로 약정합니다(법 15조① 단서, 방식 **검증 필요**).
