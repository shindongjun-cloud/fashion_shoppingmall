# 주문 2단계: 설계 방법과 결정 (2026-11-25)

사용자 질문 "주문 설계하는 방법 모두 알려줘"로 시작했습니다. 결정 지점(A~O)마다 일반적인 방법을 중립적으로 비교한 뒤, 사용자가 고르거나 추천을 받아들였습니다. 이 파일은 채팅 답변 원문이 아니라 **결정과 그 이유의 요약**입니다. 테이블 정의는 `02-tables.md`, 검증 조건은 `03-integrity.md`에 있습니다.

## 1. 결정 지점 (A~O)

| 지점 | 결정 | 이유 (요약) |
|---|---|---|
| 재고 | **별도 도메인** (사용자 결정) | 선생님 목록에 없지만 주문·발주·입고가 모두 걸려서 따로 설계. 주문은 재고에 "예약 / 풀기 / 확정"을 요청하는 쪽 |
| A 범위 | 주문 + 장바구니 + **결제 전 취소**. 결제 후 취소·반품·교환은 **클레임 하나로 환불 도메인** | 결제 후 취소도 환불입니다. 돈이 돌아가는 일을 한곳에 모아 환불 금액 계산을 한 번만 만듭니다 |
| B 뼈대·줄 단위 | 주문 + 주문 상품, **물건 1개 = 1줄** (수량 칸 없음) | 쿠폰·포인트 나눈 몫이 줄마다 정수로 정해지고, 줄마다 상태가 하나라서 부분 취소·반품이 단순합니다. 옷은 같은 SKU를 3개 이상 사는 일이 드뭅니다. 화면에서는 "× 2"로 묶어 보여 줍니다 |
| C 스냅샷 | 주요 칸 복사 (이름, 컬러, 사이즈, 추가 옵션, 가격, 이미지, 과세, 반품 조건) | 상품 전체 버전 관리(C-3)는 너무 무겁고, JSON(C-4)은 DB가 검사·집계할 수 없습니다. 소재가 바뀌면 새 상품 코드로 만들기로 해서(P-27) 소재 스냅샷은 필요 없습니다 |
| D 상태 | **주문 = 돈, 주문 상품 = 물건** (D-3) | "부분 취소 + 배송 중" 같은 조합 상태가 생기지 않습니다. 화면 요약은 계산해서 보여 줍니다 |
| E 금액 | 주문 1행에 **칸으로** 저장 (E-2), 상품 합계 칸 유지 | 한 행 CHECK로 계산식을 검사합니다. 상품 합계는 무료배송 기준, 쿠폰 최소 금액, 반품 배송비 판단의 근거입니다 |
| F 배송지 | 주문 1건 = 받는 사람 1명 (F-2) | 여러 명에게 보내려면 주문을 나눕니다. 배송지별 배송비, 출고, 변경이 복잡해지지 않습니다 |
| G 주문자 구분 | 주문에 주문자 구분 복사 + (고객ID, 구분) 복합 FK (G-1) | 비회원 쿠폰·포인트 금지를 한 행 CHECK로 검사합니다. 비회원 주문을 회원 주문으로 바꿀 수 없습니다 |
| H 주문번호 | 날짜 + 무작위 8자리 (H-3) | 고객이 읽고 전화로 불러 줄 수 있습니다. 비회원 조회는 비밀번호 + 5회 잠금 + 세션 토큰으로 지켜서 번호 추측은 문제가 되지 않습니다 |
| I 장바구니 | 회원만 DB, 비회원은 브라우저 (I-2) | 비회원 장바구니를 DB에 둬도 얻는 것이 적습니다. 로그인하면 합칩니다 |
| J 결제 전 주문 | "결제하기"를 누르면 결제 대기 주문 생성 (J-1). 만료는 ① 1분 주기 작업 + ② 조회 시 만료 무시 + ③ 결제 시작 때 예약 연장, 결제 중이면 만료 건너뜀 | ③이 없으면 결제 도중 예약이 풀려 다른 사람이 가져갈 수 있습니다 |
| K 재고 시점 | 주문할 때 예약 (K-2) | 만료되면 예약이 풀리고 다른 사람이 살 수 있습니다 |
| L 부가 서비스 | 상품이 아닌 서비스로 따로 (L-2) | 선물 포장을 가짜 상품으로 넣으면 목록, 재고, 통계, 무료배송 기준이 모두 오염됩니다 |
| M 주문 변경 | 배송지 변경은 버전 행(M-1), 돈·물건이 움직이는 변경은 클레임(M-2, 환불 도메인) | |
| N 출고 | 출고(상자)를 따로 두고 주문 상품이 가리킴 (N-2, 배송 도메인) | 주문 상품에 송장 칸을 두면 같은 송장이 여러 줄에 반복되고 재배송 때 덮어써집니다 |
| O 보관·파기 | 주문 행은 영구 보관, **개인정보만 파기** (O-1, 사용자 결정) | 시행령 6조①로 기간 확정 (아래 3번) |

### 추가로 정한 것
- 쿠폰·포인트는 주문할 때 줄마다 **나눠 적음(안분)**. 나머지 원은 소수점이 큰 줄에 붙입니다. 부분 취소 때는 그 줄의 실결제 금액만 환불합니다. 쿠폰 조건이 깨졌다고 할인액을 빼면 위약금으로 볼 여지가 있어 하지 않습니다(**검증 필요**).
- 주문자 정보를 따로 두는 이유: 회원이 탈퇴해 고객 개인정보가 파기돼도 주문 기록은 보관 기간 동안 남아야 하고, 개인정보를 한곳에 모으면 권한과 파기가 단순합니다.
- 결제 후 품절이 생기는 이유는 전산 재고와 실물의 차이(불량, 분실)입니다. 그래서 "판매자 사유 품절 취소" 흐름이 꼭 필요합니다.
- 주문 배송지는 처음에 이력 테이블을 따로 두었다가 칸이 거의 겹쳐서 **버전 행 1개 테이블**로 합쳤습니다. 덤으로 출고가 어느 버전으로 나갔는지 가리킬 수 있습니다.

## 2. 데이터를 넣어 보고 추가한 것

예시 데이터(성인 회원, 미성년 회원 한도 안, 한도 초과, 미성년 비회원)를 넣어 보며 찾은 칸입니다.
- 주문: 접속 IP 검색값·표시값, 기기 정보
- 주문 상품: 취소 일시·사유, **배송 완료 일시**(반품 기한 기준일), 교환·반품 가능 여부·제한 사유 스냅샷, 출고 기한
- 주문 배송지: 변경 요청 경로(누가 원했나 ≠ 누가 눌렀나)
- 알림: 재발송 원본 순번, 보호자 동의 요청·결과 알림
- 메모: 문의 채널
- 보호자 동의: 요청 일시·방식, 동의 시점 월 누적 결제 금액, 보호자 성인 확인 여부
- 영업일 달력: 출고 가능, 택배 집하, 고객센터 운영, 영업일 순번, 출처, 상태

## 4. 미성년자 (사용자 제안 반영)

- 결제 수단으로는 나이를 알 수 없습니다. 휴대폰 소액결제 차단이나 카드 보호자 동의는 통신사와 카드사가 하는 일이고, 계좌이체는 나이를 잡지 못합니다. 그래서 **본인인증**이 맞습니다.
- 성년은 만 19세부터입니다(민법 4조). 미성년 = 만 19세 미만.
- **비회원도 주문 전 휴대폰 본인인증**. 만 14세 미만은 주문 불가(회사 정책). 만 14~19세 미만은 법정대리인 동의.
  - 결과: 국내 휴대폰이 없는 외국인은 살 수 없습니다(국내 고객 대상이라 수용).
- **회원 단위 동의와 주문 단위 동의를 분리**합니다. 회원 미성년자는 보호자가 **구매 한도**(1회, 월)를 정하고, 한도 안 주문은 사전 허락, 넘으면 그 주문만 보호자가 인증·동의합니다. 한도는 민법 6조 "처분을 허락한 재산"의 증거가 될 수 있습니다(**검증 필요**).
- 고객 도메인에 법정대리인, 보호자 구매 한도를 추가하고, 주문에 주문 보호자 동의를 둡니다.

## 5. 선물하기 (사용자 요청)

| 정할 것 | 결정 |
|---|---|
| 누가 | 회원만 |
| 수령인 변경 범위 | 같은 상품의 옵션(컬러, 사이즈, 추가 옵션)만. 할인은 상품 단위만, 유료 옵션 없음이라 차액이 없음. 주문자가 변경을 막는 칸은 두지 않음(받는 사람이 고르는 편이 교환이 줄어듦) |
| 수령인 정보 | 주문자에게 받지 않음. 링크는 주문자가 카카오톡 공유나 링크 복사로 직접 전하고, 수령인이 이름·전화번호·주소를 입력. 수락 전 재알림·만료 안내는 주문자에게 |
| 수령인 본인 확인 | 하지 않음. 링크 잘못 전달은 주문자 책임(이용 조건에 명시). 수락하면 주문자에게 가린 이름·지역을 알림, 상품 준비 전까지 취소 가능 |
| 재고 | 결제 때 주문자가 고른 SKU 예약, 수령인이 옵션을 바꾸면 한 번에 옮김(품절이면 변경 불가, 이전 예약 유지). 예약 만료 = 수락 기한 |
| 수락 기한 | 7일. 지나면 자동 취소 + 환불 |
| 지역 추가 배송비 | 회사 부담 (혜택으로 안내) |
| 나에게 선물하기 | 수령인이 입력한 휴대폰 번호가 주문자 번호와 같으면 차단 (주소는 가족 선물이 막혀서 기준으로 쓰지 않음) |
| 출고 기한 | 수락일 + 3법정영업일 (공급 시기 약정, **검증 필요**) |
| 교환·반품 | 수령인은 교환만, 반품·환불은 주문자 (**검증 필요**) |

## 7. 브랜드 발주 (구매·생산)

고객 주문과 상대, 법, 흐름, 권한이 모두 달라 **분리**합니다. 재고 도메인과 함께 설계합니다.
- 비유: 부자재 + 상품 원가 구성 항목 = **레시피**(셔츠 1벌에 단추 8개), 발주 = **장보기 영수증**(단추 1,600개 주문), 고객 주문 = **손님 주문서**.
- 상품 도메인: 부자재(기준) 추가, 원가 구성 항목에 부자재ID.
- 구매·생산 8개: 발주(머리 1개, 구분 = 자재/생산), 자재 발주 품목, 생산 발주 수량, 자재 입고, 자재 입고 품목, 사급 자재 지급, 매입 대금 지급, 생산 발주 이력. 발주 머리를 하나로 합쳐 매입 대금 지급이 FK를 걸 수 있게 했습니다.
