# 6단계: 데이터 무결성 검증 조건 — 주문 (2026-11-25)

주문 도메인 14개 + 공통 2개 테이블(`02-tables.md`)의 검증 조건입니다. 고객 도메인에 추가한 23~25번 테이블의 조건(C-66~C-80)은 `../01-customer/03-integrity.md`에 있습니다.

- **검사 방법의 뜻**(CHECK, UK, FK, 권한, 트리거, 앱, 점검)과 **DB·앱 나누기 기준**, **앱 + 점검으로 지킬 때 꼭 하는 것 5가지**는 `../01-customer/03-integrity.md` 앞부분과 같습니다.
- **공통 조건 G-01~G-16**(시스템 칸, 상태·구분 값 목록, 금액 0 이상 정수, 암호문·검색값·표시값 형식, 기록 테이블 추가만 등)은 주문 테이블에도 그대로 적용되므로 다시 적지 않았습니다.
- 개수: 주문 O-01~O-126 (126개) + 고객 추가 C-66~C-80 (15개) = **141개**. (채팅에서 "O 121개"라고 적은 것은 잘못 센 것이고, 번호는 채팅 그대로 유지합니다.)
- 2026-11-26 결제 설계 때 O-127~O-129 3개를 추가했습니다(맨 아래). 주문 조건은 모두 **129개**이고, 트리거 T1·T2가 결제 상태를 함께 봅니다. 결제 조건은 `../04-payment/03-integrity.md`에 있습니다.
- 2026-11-27 배송 설계 때 O-130~O-141 12개를 추가했습니다(맨 아래). 주문 조건은 모두 **141개**입니다. 배송 완료가 주문 상품의 배송 완료 일시·자동 확정 예정 일시를 채우는 연쇄는 배송 트리거 T10이 합니다(`../05-delivery/03-integrity.md`).
