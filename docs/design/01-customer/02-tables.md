# 고객 도메인 테이블 정의 (22개, 2026-11-24)

선생님 9단계 중 2~3단계 결과입니다. 결정 과정은 `01-design-methods.md`(설계 방법)와 아래 "결정 요약"에 있습니다.

- 시스템 칸 4개(생성일시 createdAt, 생성자 createdBy, 수정일시 updatedAt, 수정자 updatedBy)를 모든 테이블 끝에 둡니다. 생성자·수정자는 회원·관리자·시스템이 섞이므로 FK가 없습니다. 선생님 방식(created_by 스네이크 표기)으로 바꿀지는 4단계에서 정합니다.
- 암호문은 `○○Encrypted`, 검색값은 `○○Hash`(비밀키 해시 HMAC), 표시값은 `○○Masked`입니다. 비밀번호·조회 비밀번호는 느린 전용 해시(bcrypt·argon2)입니다. 암호화 키와 해시 비밀키는 DB가 아니라 서버 설정(.env)에 둡니다.
- 행을 실제로 삭제하는 테이블(회원 배송지 주소록, 회원 체형 정보)은 상태 칸이 없습니다(규칙 예외).

## 결정 요약

| 주제 | 결정 |
|---|---|
| 뼈대 | 로그인 계정 – 회원 / 비회원 – 고객 – 고객 개인정보 (방법 3 계정·고객 분리 + 방법 2 개인정보 1:1 분리 + 방법 4 슈퍼/서브타입) |
| 대상 | 국내 고객만, 만 14세 이상만 회원가입 (법정대리인 동의 테이블 없음) |
| 사업자 | 사업자 회원가입 없음. 결제할 때 현금영수증(소득공제 / 지출증빙, 사업자번호)으로 처리 → 결제 도메인 |
| 로그인 수단 | 계정 1 : N. 자체(아이디·비밀번호), 네이버, 카카오, 구글 |
| 가입 | 수단과 관계없이 본인인증 1회 필수 |
| 중복 가입 | DI 검색값(UK) + CI 검색값. 자동 연결 금지, 새 수단은 로그인한 상태에서만 연결. 기존 수단을 못 쓰면 본인인증으로 복구 |
| 비밀번호 | 영문 + 숫자 + 특수문자 8~16자. 아이디·생년월일·휴대폰 포함 금지, 같은 문자 3번 연속 금지, 직전 비밀번호 금지 |
| 잠금 | 자체 로그인 연속 10회 실패 → 자체 수단만 잠금(소셜은 사용 가능). 본인인증 + 비밀번호 재설정으로 해제, 자동 해제 없음. IP 1시간 30회 실패 시 차단 |
| 찾기 | 아이디: 본인인증 → 가린 아이디 표시 + 이메일·문자 선택 발송. 비밀번호: 본인인증 → 바로 재설정 (다른 기기 로그인 종료) |
| 주소 | 회원 배송지 주소록 1:N, 최대 20개, 주문 때 스냅샷. 주소 검색 API로 입력. 실제 삭제 |
| 상태 | 회원: 정상 / 휴면 / 정지 / 탈퇴 요청 / 탈퇴 + 이력. 비회원: 사용 / 조회 잠금 / 회원 연결됨 / 개인정보 파기 |
| 휴면 | 상태만 바꿈(분리 보관 없음). 1년 동안 로그인·주문 없음. 30일 전 알림, 본인인증으로 해제 (법 **검증 필요**) |
| 탈퇴 | 요청 → 보류(진행 중 주문) → 유예 7일 → 완료 / 철회. 계정 삭제, 개인정보 파기, 고객·회원 행은 남김. 재가입 제한은 CI 검색값만 기간 보관 |
| 회원 등급 | 정책 버전 + 등급 + 혜택 + 이력. 최근 6개월 실결제 금액 |
| 비회원 | 주문 1건당 비회원 1명. 조회 비밀번호 5회 실패 → 30분 잠금, IP 1시간 20회 차단. 가입 후 주문을 회원 계정으로 연결 가능(자동 연결 없음) |
| 다른 도메인으로 | 미성년자(만 14~18세) 구매 보호자 동의 → 주문·결제(**검증 필요**), 환불 계좌 → 환불, 포인트·쿠폰 → 포인트·이벤트 |

## 1. 기본

### 1. 고객 (Customer)
| 키 | 논리명 | 물리명 | 설명 |
|---|---|---|---|
| PK | 고객ID | customerId | 주문, 개인정보, 동의가 가리키는 번호입니다. 회원ID와 비회원ID는 이 값과 같습니다. 탈퇴해도 남습니다. |
| | 고객 구분 | customerType | 회원 또는 비회원입니다. 회원·비회원 테이블 중 정확히 한 곳에만 행이 있어야 합니다(DB 검사). 한 번 정하면 바뀌지 않습니다. |
| | 생성일시 | createdAt | 데이터가 처음 생성된 시간 |
| | 생성자 | createdBy | 데이터를 생성한 사용자 |
| | 수정일시 | updatedAt | 마지막으로 수정된 시간 |
| | 수정자 | updatedBy | 마지막으로 수정한 사용자 |

값이 바뀌지 않아 상태 칸이 없습니다. 비회원이 나중에 가입해도 비회원이 회원으로 바뀌지 않습니다. 새 회원이 생기고, 비회원 주문을 그 회원에게 연결합니다.

### 2. 회원 (Member)
| 키 | 논리명 | 물리명 | 설명 |
|---|---|---|---|

### 3. 비회원 (Guest)
| 키 | 논리명 | 물리명 | 설명 |
|---|---|---|---|
| PK, FK | 비회원ID | guestId | 고객ID와 같은 값입니다. 비회원 주문 1건마다 1명입니다. |
| | 주문 조회 비밀번호 해시 | lookupPasswordHash | 주문할 때 정한 비밀번호입니다. 느린 전용 해시(bcrypt·argon2)로 저장합니다. |
| | 연속 조회 실패 횟수 | lookupFailCount | 성공하면 0이 됩니다. 5가 되면 잠깁니다. |
| | 조회 잠금 일시 | lookupLockedAt | 잠긴 때입니다. 30분이 지나거나 문자 인증을 하면 풀립니다. |
| | 마지막 조회 일시 | lastLookupAt | 비회원이 주문을 마지막으로 조회한 때입니다. |
| FK | 연결된 회원ID | claimedMemberId | 이 비회원이 나중에 가입해서 주문을 회원 계정으로 가져갔으면 그 회원입니다. |
| | 회원 연결 일시 | claimedAt | 주문을 회원 계정으로 가져간 때입니다. 한 번만 할 수 있습니다. |
| | 개인정보 파기 예정 일시 | destroyScheduledAt | 주문 기록 보관 기간이 끝나는 때입니다(기간 **검증 필요**). |
| | 비회원 상태 | status | 사용, 조회 잠금, 회원 연결됨, 개인정보 파기 중 하나입니다. |
| | 생성일시 | createdAt | 데이터가 처음 생성된 시간 |
| | 생성자 | createdBy | 데이터를 생성한 사용자 |
| | 수정일시 | updatedAt | 마지막으로 수정된 시간 |
| | 수정자 | updatedBy | 마지막으로 수정한 사용자 |

비회원 개인정보(이름, 휴대폰, 이메일)는 고객 개인정보에, 개인정보 수집 동의는 고객 약관 동의 이력에 둡니다.

### 4. 고객 개인정보 (CustomerPrivacy)
| 키 | 논리명 | 물리명 | 설명 |
|---|---|---|---|

| | 이름 암호문 | nameEncrypted | 회원은 본인인증으로 받은 이름, 비회원은 주문자 이름입니다. |

| | 생일 월일 | birthMonthDay | 예: 0315. 생일 쿠폰에 씁니다. 연도가 없어 사람을 특정하기 어렵습니다. |

| | 휴대폰 번호 표시값 | phoneMasked | 예: 010-****-1234. |
| | 이메일 암호문 | emailEncrypted | 알림과 아이디 찾기 발송에 씁니다. |
| | 이메일 검색값 | emailHash | 비밀키 해시입니다. |
| | 이메일 표시값 | emailMasked | 예: hon***@naver.com. |
| UK | DI 검색값 | diHash | 중복 가입 확인값입니다. 회원만 있고, 값이 있을 때만 UK로 검사합니다. |
| | CI 검색값 | ciHash | 비밀키 해시입니다. 본인인증 업체를 바꾸거나 재가입을 제한할 때 씁니다. 회원만 있습니다. |
| | 본인인증 일시 | verifiedAt | 마지막으로 본인인증을 받은 때입니다. 비회원은 비어 있습니다. |

| | 개인정보 파기 일시 | destroyedAt | 실제로 파기한 때입니다. 파기했다는 증거가 됩니다. |
| | 생성일시 | createdAt | 데이터가 처음 생성된 시간 |
| | 생성자 | createdBy | 데이터를 생성한 사용자 |
| | 수정일시 | updatedAt | 마지막으로 수정된 시간 |

## 2. 로그인·인증

### 6. 로그인 수단 (LoginMethod)
